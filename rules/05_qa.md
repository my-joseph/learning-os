# 05_QA — Implementation Workflow, Quality Assurance & Audit Protocol

**Module Code:** `RULES-QA`  
**Applies To:** Implementation pipelines, pre-delivery verification, Notion API audits, and completion reporting  
**Prerequisite:** Must adhere to `rules/00_core.md` and applicable domain modules  

---

## PART 1 — Implementation Workflow

For every implementation task, AI must follow this strict 10-step sequence:
1. **Read Applicable Rules:** Read `00_core.md` plus relevant domain modules (`01_arch`, `02_pedagogy`, `03_stem`, `04_code`, `06_template_contract`, `07_problem_generation`).
2. **Confirm Scope:** Confirm the user's explicitly requested scope and boundaries.
3. **Inspect Notion Architecture:** Inspect actual databases, records, properties, relations, and views.
4. **Identify Dependencies:** Check existing content, parent/child links, and prerequisites.
5. **Check Conflicts:** Identify potential conflicts, shared-database effects, or shared properties.
6. **Plan Implementation:** Prepare a step-by-step implementation plan before touching data.
7. **Execute Authorized Changes:** Execute only authorized modifications.
8. **Automated Audit:** Run programmatic verification on all modified pages and assets.
9. **Verify Results:** Inspect saved blocks to confirm zero errors or link regressions.
10. **Report Results:** Deliver a structured implementation report detailing completed work and limitations.

---

## PART 2 — Quality Assurance Checklist

Before marking any implementation task complete, verify each of the following 5 dimensions:

### 1. Data Integrity
- [ ] Record created/modified in the correct database.
- [ ] All database properties accurately populated (no missing Objectives, Expected Outputs, or Priority).
- [ ] Two-way database relations verified (Topic ↔ Chapter ↔ Unit ↔ Resources).
- [ ] All referenced sources in `Learning Resources` have complete metadata (`Title`, `Type`, `Topic/Area`, `URL`, `Key Notes`).
- [ ] Zero unintended duplicate records created.
- [ ] Zero historical user notes, drill logs, or scores overwritten.

### 2. Content & Formatting Quality
- [ ] Content strictly matches the actual learning objective.
- [ ] Depth and rigor are appropriate for the intended level.
- [ ] Section structure follows reference guidelines without being rigidly cloned.
- [ ] **Strict English-Only:** 100% of page content is in English with zero non-English (e.g., Thai) text.
- [ ] **Vertical Mathematical Derivations:** Every equation transformation stacks vertically using native Notion `equation` blocks (`\begin{aligned}`).
- [ ] **Multi-Level Practice Guide:** 4 required categories (Core Skills, Prior Blend, Traps, Cross-Subject) with indented sub-bullets and zero static problem dumps.
- [ ] **Zero Broken Mentions:** Every workspace ID (`MTH-*`, `PHY-*`, `PRG-*`, `R***`) is tokenized as a clickable Notion `@page` mention.

### 3. Source Quality & Attribution
- [ ] Sources used are reputable and directly relevant.
- [ ] Resource access verified (distinguishing URL accessible vs. content verified).
- [ ] Citations and original links accurately preserved.
- [ ] Gaps or unverified claims explicitly flagged.

### 4. Learning System Invariants
- [ ] `Status` (initial completion) and `Mastery (0-4)` (retention fluency) remain completely separate.
- [ ] Review properties (`Mastery`, `Last Reviewed`, `Next Review`) remain consistent.
- [ ] Database progress rollups and formulas remain accurate.
- [ ] Existing user workflows are preserved.

### 5. Scope Protection
- [ ] Modifications strictly restricted to the authorized scope.
- [ ] Zero changes made to unrelated Topics, Tracks, or shared schemas.
- [ ] No unauthorized global database properties added or renamed.

## PART 3 — Scripted Notion API Audit Checklist

For automated verification via Python scripts (`audit_page()`):
- **Unlinked Plain Codes Check:** Regex pattern `\b(MTH-T\d+(-C\d+(-U\d+)?)?|PHY-T\d+(-C\d+(-U\d+)?)?|PRG-T\d+(-C\d+(-U\d+)?)?|R\d{3})\b` must return **0 matches** in plain text blocks (`unlinked = 0`).
- **Page Mention Check:** Every referenced entity must exist in `t.get("type") == "mention"` with `mention.get("type") == "page"`.
- **Image Block Check:** Zero external hotlinks to third-party domains (`upload.wikimedia.org`); all images must be native Notion-hosted files (`type: "file"` or `type: "file_upload"`).
- **Block Count Check:** Total page blocks must meet baseline standards (Units $\ge 40$ blocks, Chapters $\ge 45$ blocks).

---

## PART 4 — Implementation Reporting Protocol

After completing an implementation, report to the user:
1. **Inspected Scope:** Databases, records, and properties evaluated.
2. **Executed Changes:** Pages created, updated, or restructured (with block counts).
3. **Audit Verification:** Exact Notion API audit results (mention counts, unlinked tokens, image types).
4. **Preserved User Data:** Specific confirmation that historical user statuses, drill logs, and notes remain untouched.
5. **Limitations & Next Steps:** Any remaining dependencies, prerequisites, or recommended follow-up actions.
*Never claim that an action was completed or verified unless it actually succeeded.*
