# CLAUDE.md (v0 — short on purpose; project is being refactored)

> **Git delivery policy:** See `rules/00_core.md` §10. This is the canonical merge-policy statement; follow any narrower task-specific instruction.

## Project Overview
- LearningOS: a Notion-hosted curriculum (Topic → Chapter → Unit) plus local-first generators for practice drills (`MTH`/`PHY` math, `PRG` code) and project labs.
- Python scripts generate/verify content and write to Notion; a Next.js "Practice Studio" shows drills; code is edited in the user's own local editor (e.g. VS Code).
- Chat with the user in polite Thai. All content written to Notion/drills must be English.

## Rules (read first, do not copy here)
- Before any task: read @rules/README.md (task→module routing) and @rules/00_core.md, then the domain module.
- Rule edits: change `rules/*.md` and commit. Rules are local-only; they are **not** synced to Notion (old Notion rule pages are stale; never read rules from Notion).

## Tech Stack
- Python 3.14 (stdlib `urllib` for Notion REST; `sympy`, `numpy` for math engine). Deps: `requirements.txt` (runtime), `requirements-dev.txt` (+pytest, ruff). CI runs Python 3.12.
- Node 24 / npm 11. `practice-studio/`: Next.js 14.2.35, React 18, TypeScript (strict), Tailwind 3, KaTeX, three.js.
- Labs: TypeScript run via `node --experimental-strip-types` (no build step).

## Commands (checked against the repository and CI workflow 2026-11-20)
- Studio (run in `practice-studio/`): `npm ci`, `npm run dev` (http://127.0.0.1:3000, bound to localhost only), `npm run lint`, `npm run build`.
- Generate drills (run from repo root): `python3 -m math_engine.generate --unit <UNIT> --count <N> --difficulty <D>` and `python3 -m code_engine.generate --unit <UNIT> --count <N>` (`--help` verified; full run not verified).
- Lab (run in `labs/LAB-PRG-T01-C04-02/`): `npm test` fails until solved; `npm run test:reference` and `npm run check:reference` are available (`check:reference` runs reference tests + lint + `tsc`). `npm run submit` writes to Notion — only on request.
- PRG lint toolkit (run in `tools/lint/`): `npm ci` installs ESLint 9 + `tsc` for PRG drill workspaces and labs. In any PRG drill workspace or lab, `npm run check` runs tests + lint (+ `tsc --noEmit` for TypeScript). Check all PRG drill reference solutions from repo root: `.venv/bin/python -m code_engine.lint_check --all`.
- Python tests (repo root): `.venv/bin/python -m pip install -r requirements-dev.txt && .venv/bin/python -m pytest -n auto` (pytest-xdist; full suite ~3.5 min). Fast loop without the slow PRG tests (ESLint/tsc): `-n auto -m "not prg"` (~40 s); PRG only: `-m prg` (needs `npm ci` in tools/lint). Main `.venv` `bin/pip` launcher is broken, so use `-m`. Hermetic, no Notion/network. Studio unit tests: `npm run test:telemetry` in `practice-studio/`.
- CI pins Python 3.12 and Node 24. `.github/workflows/ci.yml` runs ruff, Python tests and vault checks, conditional PRG tests/lint, Studio lint/build/telemetry tests, and lab reference checks. The Python job is skipped only for PRs whose changed files are all under `practice-studio/` or `docs/studio_design.md`, with no deletions or renames. The PRG job runs when PRG/shared paths change; pushes to `main` run all jobs. No Makefile/Dockerfile.

## Conventions (target — apply to new/changed code)
- Python: ruff format + lint, type hints on public functions, one shared Notion client on stdlib `urllib` (no new deps), secrets only from env.
- TypeScript: strict per `practice-studio/tsconfig.json`; must pass `next lint`.
- Drill IDs: `DRL-<UNIT>-NN`; content specs live in `drills/data/<UNIT>/`. `practice-studio/src/types/drill.ts` documents the Studio-facing TypeScript shape; use the Python ingest/checker modules for full on-disk and server-only fields.
- Lint/format (repo root): `ruff check .` and `ruff format --check .` (config `ruff.toml`; `archive/` excluded; do not strip trailing whitespace inside string literals — it is generated output). CI enforces both.
- Commits: conventional (`feat(scope):`, `fix:`, `refactor:`, `docs(rules):`).

## Workflow
- Follow the canonical branch, PR, and merge policy in `rules/00_core.md` §10; `.githooks/` enforce the main-branch guard when enabled with `git config core.hooksPath .githooks`.

## Gotchas / Do-Not
- Never commit or print `.env` (`NOTION_TOKEN`, `NOTION_DATABASE_ID`). `.env`, `.venv`, `node_modules` are gitignored and absent in fresh worktrees; scripts read `.env` relative to the CWD, so run from repo root.
- Studio deep links: Notion pages and links target `/math/<DRILL_ID>` (`DRL-MTH-*`, `DRL-PHY-*`), `/code/<DRILL_ID>` (`DRL-PRG-*`) with optional `?q=<QID>` (e.g. `?q=Q03`) to open a specific problem, and `/code/lab/<LAB_ID>` (`LAB-*`) with optional `?m=<MILESTONE>` (e.g. `?m=M2`) to open a specific milestone (unknown `q`/`m` falls back to the first problem/milestone, and wrong-workspace URLs redirect to the matching route). Legacy `/?drill=<ID>&q=<QID>` links redirect to the workspace route, and plain `/` redirects to the last opened drill or the first available drill.
- Root is canonical for `math_engine/`, `code_engine/`, `drills/`, `id_map.json`, `notion_sync/`. `practice-studio/` has no copies (only a `code_engine` symlink to `../code_engine`); the Studio API routes read root via `practice-studio/src/lib/paths.ts`. Never recreate copies; `code_engine.generate` no longer mirrors into `practice-studio/`.
- 34 one-shot scripts (`*_builder.py`, `upgrade_*`, `create_*`, `fix_*`, `deploy_*`, `clean_*`, `patch_*`, ...) live in `archive/` and mostly write to Notion. Never run them unasked; if required: `PYTHONPATH=. python3 archive/<script>.py` from repo root (`archive/apply_rules_and_test_pages.py` re-exports the live helpers for them). All Notion code is in the `notion_sync/` package: `client` (REST client + `.env` loader; process-wide IPv4/timeout on import; TLS always verified; retries only network errors/409/429/5xx; raises `MissingNotionToken` before any request; `replace_page_content` appends before deleting), `blocks` (rich text/block builders), `drill_sync` (zero-leak validator + save + Notion sync; spawned by the studio `sync-notion` route; pass `--content-only` on the CLI to refresh a drill's Notion page with merged progress without writing local progress, unit reviews, review cache, or Mistake Log). Root `.py` files: `quality_rules.py` (shared quality gates; reads `skills_taxonomy.json`) and `progress_store.py` (learner progress storage under `progress/`).
- Never hand-edit `id_map.json` (Notion page-ID registry, incl. `CON-*` concept keys).
- Thai exam PDF indexing uses optional `pdftoppm` + Tesseract (`tha+eng`) OCR for empty or legacy-font-garbled pages; install with `brew install tesseract tesseract-lang`, and worker prompts link cached page images when OCR may miss formulas.
- Drill files in `drills/data/` are **content only**. Learner progress (problem `state`, `sessionSummary`) lives in `progress/<DRILL_ID>.json` (gitignored; `progress_store.py` / `practice-studio/src/lib/progress.ts`). Never write practice results into a drill file; `tests/test_progress_store.py` enforces it.
- Drill hints/placeholders must never leak the answer (zero-leak rule, `rules/00_core.md` §6). AI-written math prompts must not give away the solution either (`rules/07` §4.7, enforced at ingest); audit with `python scripts/audit_solution_leaks.py [UNIT] [--display]` (`--display` is advisory: `display` is the hidden "Show equation set-up" box and may restate the given expression, so a flag there is not a gate failure).
- Notion multi-select values cannot contain commas; use only whitelisted Notion icon names.
- `code_engine.generate` writes CWD-relative side effects (`drills/workspace/<ID>/`). Tests must `monkeypatch.chdir(tmp_path)`.

- Drill scope: a unit code (`MTH-T01-C04-U03`) gives a unit-only drill; a chapter code gives a mixed drill over its units. Archetypes carry `unitCode`; an archetype's `level` is a base level, not a cap. Vault health: `python -m scripts.vault_report [UNIT|CHAPTER] [--log]` shows which levels each archetype has earned (ingested drills) or failed (issue log); computed, never hand-edited.
- Cross-unit bridge drills: `math_engine/reasoning_vault/MTH-BRIDGE.json` stores multi-unit L3+ bridge archetypes (`unitCodes`, `junction`, `skillsByUnit`, validated by `code_engine.quality_checks --check-vaults`); dormant until ≥2 math units pass (mastery ≥ 2).
- Bridge eligibility: `python -m scripts.bridge_scope [--json] [--min-mastery N]` checks local `progress/` (read-only, no Notion calls) for passed units and eligible bridge archetypes; `ai_drill_ingest` enforces ≥2 units, L3+ `blindSolve`, and `steps[].unit` coverage, and `source_gap` reports `Bridge candidates`.
- Starting a unit: the `start-unit` skill builds the unit's archetypes, runs `scripts.source_find <UNIT> --plan` for both MTH and PRG units (running `synthesize-source` steps 3–5 — worker batches until saturation/budget, then Claude `source_gap` + vault update/reviewer — before the Notion page if planned batches or carried-forward cards exist), writes its Notion page to the v4 structure (rules/02 §7a/§7b) with `python -m notion_sync.unit_page` (new pages only; existing pages are extended with `--mode add`, `--move-section-to-end "<heading>"`, and `--renumber`, never rewritten; the learner's "My Implementation & Mistake Log" is never touched), then makes the first drill and (for MTH) checks Similar variant coverage (`variant_bank --coverage`). Synced drill results are inserted at the end of that section.
- Page standard: `python -m scripts.page_audit <TOPIC|CHAPTER|UNIT>` checks Notion pages against rules/02 §7a (read-only; FAIL/WARN). Pages are written only with `notion_sync.unit_page` (`--set "Resources=R036"` sets relations); no direct Notion API writes to learning pages.
- PRG pages (rules/02 §7b): 7-section unit standard (Core Concepts & Mental Model, Core Patterns + "Why this works", Worked Code Examples L1 Direct / L2 Edge Case|Refactor / L3 Bug Contrast, Practice Guide citing QC-/U- ids, 3–4 Active Recall toggles, My Implementation & Mistake Log, Completion Checklist) + "Chapter Lab" on chapters with labs; `unit_page` supports `code` blocks and `page_audit` runs the PRG profile for `PRG-*`.
- Spaced review: syncing a practised drill writes evidence-based `Mastery (0-4)` (max 3; learner sets 4), `Last Reviewed` and `Next Review` to each unit it covers (rules/01 §9) and merges the same values into `progress/_review_schedule.json` (`pilot/progress/_review_schedule.json` in pilot mode). Rebuild the cache read-only from Notion unit pages with `python -m scripts.review_cache --rebuild`.
- Figures: every archetype has `figureBuilders` or a `figureNone` reason (gate; rules/03 §3.1), so drills on shapes, graphs, number lines or the complex plane get figures without being asked. Unknowns are labelled `?`. Studio (`practice-studio/src/components/MathFigure`) and `math_engine/figure_svg.py` (Notion) draw the same spec; `notion_sync.unit_page` takes `figure` blocks and uploads them (`notion_sync/figures.py`).
- Weak spots: `python -m scripts.weak_spots [UNIT|CHAPTER]` reads learner progress and says which traps the learner keeps falling into and what to drill next (read-only).
- Skills: `health-check` audits system health read-only; `drill-quality` reports practice evidence via `scripts.drill_quality`; `dispatch-worker` manages isolated worker jobs. Use their triggers and safety rules in `.claude/skills/`.
- PRG review runner & records: `python -m code_engine.review_run <DRILL_ID|LAB_ID> <QID|MILESTONE> [--json]` runs Layer 1+2 for one drill problem or lab milestone (read-only); `python -m scripts.review_record {add,explain,dispute,show}` records rubric-bound reviews in `progress/<DRILL_ID|LAB_ID>.json` (`state.reviews[]`, never in `drills/data/` or `lab.config.json`). The learner asks for a review with the `review-code` skill ("ตรวจโค้ด <DRILL_ID> <QID>" or "ตรวจโค้ด <LAB_ID> M2").
- `scripts/practice.py` is a pilot-only terminal practice tool; it is not the production learner workflow. Practice Studio is the production interface.
- `math_engine/answer_check.py` keeps sign diagnostics domain-aware: the `$i^2 = -1$` reminder is for complex expressions, and solution-set hints mention both signs only for symmetric roots.
- Pilot mode: set `LEARNINGOS_PILOT=1` for AI stand-in practice under `pilot/` (`pilot/progress/`, `pilot/workspace/`, `pilot/labs/`); skips learner-state Notion writes and tags new issues with `source="pilot"`.
- PRG curriculum v2 (2026-11-16): codes follow `docs/prg_curriculum_v2.md`; old→new map in `docs/prg_migration_map.json`; retired pages have Full ID `RETIRED-<old>`.
- Issue log: mistakes you or a reviewer/gate catch are logged with `python -m scripts.issues add ...` (rules/00_core.md §11) and cleared in batches; flag `urgent` ones on the first line of your reply. Learner never previews or approves drills (they study them); the `new-math-drill` skill uses a reviewer subagent instead.
- PRG drills: the `new-code-drill` skill (`.claude/skills/new-code-drill/SKILL.md`) mirrors `new-math-drill` — inspect unit page + `vault_report` + `weak_spots`, run `python -m code_engine.ai_drill_ingest --check <draft.json>`, blind-solve subagent, reviewer subagent, ingest, `pytest`, and `notion_sync.drill_sync` (delivery follows rules/00_core.md §10).
- PRG project labs: the `new-project` skill (`.claude/skills/new-project/SKILL.md`) builds chapter labs (`docs/prg_curriculum_v2.md` §4) and extra projects on request (§9, "ขอโปรเจคเพิ่ม <CHAPTER|TOPIC>") — `python -m code_engine.lab_ingest --check <lab_dir>`, blind-solve subagent, reviewer subagent, finalise (`lab_ingest <lab_dir>`), `pytest`, and `notion_sync.lab_sync` (delivery follows rules/00_core.md §10).
- Source-synthesis pipeline (MTH & PRG): raw materials live in `sources/` (math PDFs) and `sources/prg/<family>/` (PRG git clones of `.js`/`.ts`/`.py`/`.md`/`.json` files) in the main checkout (gitignored; override with `LEARNINGOS_SOURCES_DIR`; registry, allowed use `REUSE`/`CORES`/`scope`/`NO-AUTOMATION`, priorities & licences in `docs/sources.md`, ranked to-add list in `docs/source_backlog.md`, OpenStax is scope-only, `NO-AUTOMATION` is never indexed automatically). Run `python -m scripts.source_find <UNIT> --plan [--budget-pages 30 --budget-items 40] [--refresh]` (caches extracted text in `sources/_index/pdf_*.json` or `code_*.json`, uses MTH/PRG entries in `unit_terms.json`, warns on unregistered folders under `sources/` or `sources/prg/`, skips `scope`-only and `NO-AUTOMATION` families plus unchanged pages/chunks already in `sources/_cores/_ledger.json`, and writes `sources/_index/plan_<UNIT>.json`). Generate worker batch prompts with `python -m scripts.extract_cards_job <UNIT> --batch <k>` (`schema.json` for MTH, `prg_schema.json` for PRG with optional `reuse` attribution block on `REUSE` families; run via `tools/agents/run-worker.sh` with `DONE_FILE`; `--commit <batch.jsonl>` validates via `validate_core_card` enforcing no copied wording/numbers/code/identifiers/test names/strings, appends to `sources/_cores/<UNIT>.jsonl`, updates `_ledger.json`, and writes `DONE_FILE`; `laterUnit` validated against `id_map.json` unless prefixed `"UNMAPPED:"`, remap with `scripts.source_cores_retag`). Check saturation with `python -m scripts.source_gap <UNIT> --novelty <batch.jsonl>` (stop after 2 consecutive batches add `< 2` new cores), review `python -m scripts.source_gap <UNIT>` (compares against `math_engine/reasoning_vault/` for MTH or `code_engine/reasoning_vault/` `cognitiveTraps`/`qualityChecks` for PRG, listing new bug patterns/`QC-*` ideas and missing archetype kinds/levels; carries forward `laterUnit`/`units` cards marked `carriedFrom`), and enforce originality via `python -m math_engine.source_cores.originality` (math text/numbers + PRG token-level Winnowing/k-gram code similarity & prompt checks, wired into `math_engine.ai_drill_ingest --check`, `variant_bank --check`, `code_engine.ai_drill_ingest --check`, and `code_engine.lab_ingest --check` via `--originality`, default ON when `sources/` exists).
- Source synthesis skill: `.claude/skills/synthesize-source/SKILL.md` runs the bounded end-to-end flow for MTH and PRG units on `"สังเคราะห์โจทย์ <UNIT>"` / `"synthesize problems for <UNIT>"` (`source_find --plan` → worker batches via `extract_cards_job` + `run-worker.sh` until saturation or budget → `source_gap` → Claude reviewed vault update → `new-math-drill` + `variant_bank --coverage`/`--add` for MTH, or `new-code-drill`/`new-project` for PRG → originality gate → PR; never shows answers or copies source material; PRG Similar/variants out of scope).
- Similar variant coverage: `python -m math_engine.variant_bank --coverage <UNIT|drill.json>` reports variant counts per `(archetypeKey, level)` used by drills and flags pairs with `< 3`; `ai_drill_ingest` prints a non-blocking warning on uncovered pairs after ingest. Fill uncovered pairs with AI-made variants via `variant_bank --add` (never seed from retired templates).
- Known gaps for topics not yet started (trigonometry functions, logarithms, calculus) are listed in `docs/backlog.md`; fix them when that topic starts.
