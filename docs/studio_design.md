# Practice Studio — design guide (v2, 2026-11-18)

For the learner's cross-screen taste and visual examples, read [design principles](design/principles.md) and the [reference gallery](design/references/README.md) before changing Studio UI. Use the [design tokens](design/system.md) and [component catalog](design/components.md) to extend shared components.

The learner's brief: clean, few tags, easy to work a problem, no confusing buttons, no visual noise or text that does not help, a clear hierarchy, and colour and type chosen for ease of use. Every Studio PR follows this file.

## Principles
1. **The problem is the page.** The current question (prompt, figure, answer) gets the most space and the strongest type. Everything else is quieter.
2. **One primary action per state.** Exactly one filled button is visible at a time (icon-only `=` inside the field, Open in VS Code, Copy review request, Next problem/milestone). Other actions are text/ghost buttons or compact dialogs.
3. **Say less.** No decorative badges, IDs, chips or status pills unless the learner acts on them. Show drill IDs in the curriculum tree and above page titles where they identify the active drill or lab. Helper text appears only when it changes what the learner does next.
4. **Empathy.** Wrong answers get calm, specific feedback in a light-tinted result card and a retry — never saturated alarm colours. Copy is short, second person, never blaming ("Not quite — check the sign in step 2"), and uses the item noun of the workspace (`Question` for math, `Problem` for code drills, `Milestone` for labs).
5. **No answers before an attempt.** Hidden content is not rendered or fetched until it is earned (see rules/00_core.md §6).

Review & Sync saves local progress before exporting results. Notion includes question and solution blocks for items with a saved check, test run, or review in the current attempt cycle. Skipped items appear as concept gaps. Pilot sync acknowledges locally.

Review & Sync shows an amber **Synced with problems** banner when a Notion write is incomplete. It lists the affected steps and keeps the success indicator off. **Retry** resumes those steps for the same saved attempt, even after reloading Studio. Changes to the drill or its saved attempt start a fresh sync.

## Playground
- The flask icon beside the theme toggle opens `/lab` and stays highlighted on Lab pages. Cards show lazy previews and open the experiment's full controls and readout at `/lab/[id]`. The Programming workspace's Labs still live at `/code/lab/[labId]`.
- `/playground/ui-components` demonstrates the core Radix + Tailwind primitives under `practice-studio/src/components/ui/shadcn/`. Keep showcase content shrinkable and wrapped at 390 px. Legacy links redirect from `/ui-poc` to UI components, from `/ui-poc/isometric` to Lever, and from `/ui-poc/isometric-math` to Disk method.
- The Shapes card and detail render the twelve decorative contours in `practice-studio/src/lib/shapes/signatureShapes.ts`. The lab grid and its figures share a 5:4 preview area in both themes.
- `Button` supports compact controls with 44 px mobile targets and 32 px desktop height, plus compact icon controls with 44 px mobile targets and 36 px desktop targets. Native buttons default to `type="button"`; `asChild` links keep their element semantics. Primary buttons use indigo-600 with white text in both themes for AA contrast.
- `Badge` supports default, secondary, outline, destructive, success, ghost, and layout-only `status` variants. Status badges use `statusTone` or `warningTone` recipes through caller classes; do not add raw status palette classes.
- Tabs keep rounded corners on segmented/contained switchers (`TabsList` `rounded-lg`, `TabsTrigger` and active pill `rounded-md`), while outline/underline tab strips (`variant="underline"` or `variant="similar"` for the Math similar-question strip) use square corners (`rounded-none`).

## Code display

- Full-file blocks show the filename, line numbers, and Copy. Bug-finding problems also let learners select lines by click or keyboard. Wrap lines switches from horizontal scrolling to wrapped lines with a single number per source line. Studio remembers the choice per browser.
- Input and Output examples, visible test assertions, and sync diagnostics wrap. Supported programming snippets use Studio's lazy-loaded Shiki grammars and GitHub light and dark themes.
- Fences in prompts, worked steps, and review text support optional filenames, line highlights, and CLI transcripts. See the [Markdown code fence syntax](design/components.md#markdown-code-fences). Reference files appear in the Reference disclosure after a passing review in the current attempt cycle.
- Run checks shows test counts and available diagnostics in a copyable Terminal block for both programming drills and labs. Hidden cases appear as aggregate counts. Private runner transcripts stay server-side.

## Layout
- Edge-to-edge flat hairline 3-pane desktop layout (`>=1024 px`) separated by `1 px` `zinc-200` / `zinc-800` hairlines:
  - **Left Sidebar**: `287 px` wide when open, collapsing smoothly to `0 px` via the sidebar toggle (`PanelLeft`) or `Cmd/Ctrl+B` (below `1024 px` opens as a mobile left Drawer). Contains the icon-only `Σ` / `</>` `WorkspaceSwitch` (height-matched to `PanelLeft`) a full-width **Search** row, and the persistent `DrillSwitcher` tree (in Programming, `Labs` and `Drills` in one scrolling list). Collapsing hides `MTH/PRG` along with the sidebar, leaving the expand button, icon-only Search, and active drill title on the left of the Top Bar. The mobile Top Bar has the same Search icon.
  - **Top Bar**: one slim row — left-aligned `PanelLeft` expand trigger and Search icon (when collapsed or on mobile), followed by the active drill title; right-aligned Reset all, Notion link, Theme toggle, and Lucide `List` Right Panel toggle.
  - **Pagination / Stepper sub-bar**: compact `QuizPaginationBar` / `Stepper` (`24 px` desktop / `22 px` mobile circles `Q1`, `Q2`, … for drills and `M1`, `M2`, … for labs, `Review` trailing clipboard step, `44 px` minimum tap targets, horizontal scroll on `<640 px`) is retained beneath the header and hidden by default via `showPaginationBar = false`.
  - **Center problem canvas**: frameless ~720 px max-width centered column (`MathWorkspace` / `CodeDashboard`; `/review` keeps its framed card).
  - **Right Panel (`Due today & What I get wrong`)**: collapsible `276 px` pane on `>=1024 px`, persistent across both Quiz and Review views, collapsing into a right Drawer below `1024 px`.

### Right panel

- **Due today** uses the item-level schedule. The toolbar badge counts only due items in the active workspace.
- **What I get wrong** shows recurring misses across Math or Code, with the active unit's entries first. Each row shows a plain name and the miss rate over its last five observed tries. Three clean tries after the last miss show **Fixed** for the rest of that day. Next to an unanswered problem or Similar tab, the disclosure is collapsed and Studio does not request mistake history.
- **Practise** opens an eight-item review session of previously missed items for that mistake, with due items first. The URL carries an opaque scope key and the session uses the Daily Review player and its existing check and completion rules. Items that are still scheduled for the future do not add to Due today.

## Colour (Tailwind tokens; light / dark)
- Neutral base & surfaces: `zinc` with `1 px` `zinc-200` / `zinc-800` hairlines, muted text `zinc-500` / `zinc-400`. Top Bar, Center problem canvas, Right Panel, Equation set-up, and dark inputs share `white` / `zinc-900` (`#18181b` dark `--background`; zero `dark:bg-zinc-950` in `src/`); Left Sidebar, Steps, and secondary panels use `--surface-panel` (`bg-surface-panel`: `#fafafa` light / `#202023` dark). The shared Tabs module provides the sliding pill for the Math and Programming navigation and the Math input and Plain text switch. Expanded Math Palette keycaps use the shared IconButton palette tone against `bg-surface-panel`. Equation rows (`MathBlock`, `StepRow`) suppress scrollbars while preserving horizontal overflow.
- One accent for the primary action: `indigo-600` (both light and dark, `>= 4.5:1`), text white.
- Typography follows the [Studio font roles](design/system.md#using-tokens).
- Lists in rendered prose use native markers through [Typeset](design/components.md#rendered-prose). Structured controls such as Visible tests and Constraints continue to use `ListDot` with the variant for that role.
- Focus indicators use keyboard-only `focus-visible` rings. Sidebar tree rows and their ellipsis triggers use inset zinc rings. Other controls use `indigo-600` in light mode and `indigo-400` in dark mode. Suppress mouse-click focus rings and browser default outlines.
- Status only, never decoration: **no yellow/amber for any answer status** (learner decision 2026-11-19). Clean first-try `correct` uses emerald green; any non-clean eventually-correct or partial answer (`assisted`: correct with help, correct on retry / score 0.5, partial / `equivalent_not_in_form`, self-score 0.5, result card `"almost"`, Review & Sync `"Assisted / partial"`) uses green outline (no fill); `wrong` uses rose; `skipped` uses a dashed zinc outline; `notTried` and unanswered `usedHelp` use a plain outline (no colour). Amber is reserved exclusively for non-status operational warnings via `warningTone` (degraded sync banner, paused timer, pending/warning toasts, hint left-borders). Status colour appears on stepper circles, tab status icons, unrounded left borders, or light status tints on result cards and selected choice states — never as a left-accent border on rounded boxes or saturated full-card fills.
- Default theme syncs live with `prefers-color-scheme`; the toggle acts as a temporary override that yields when OS preference changes or when toggled back. Contrast AA (`>= 4.5:1`) everywhere.

## Type
- Use Geist for reading and controls, Roboto Slab for prominent headings and numerals, Geist Mono for code and curriculum IDs, and KaTeX for math. The [design tokens](design/system.md#using-tokens) specify weights and size thresholds.
- Use one h1 per page. `Heading` renders the page title at 18 px and places the drill or lab ID above it when available. Use `text-base` (15 px) with `leading-relaxed` for question prompts and `text-sm` for secondary text.

## Spacing and motion
- 8 px rhythm (`gap-2/4/6/8`), generous padding inside the question card (`p-6`, `p-4` on mobile).
- Status toasts stack bottom-right (`>=640 px`) / bottom-centre (`<640 px`).
- Calm ease-out `motion/react` (`m.*` under `<LazyMotion features={domAnimation} strict>` and `<MotionConfig reducedMotion="user">`) via `practice-studio/src/lib/motion.ts` and `<Reveal>` across overlays (`Dialog`, `AlertDialog`, `Drawer`, `Popover`, `Tooltip`, `HoverCard`), `Collapsible` disclosures, `MathWorkspace` tab switches, and tactile `Button` / `ChoiceOptionGroup` press states, while static containers, badges, and inputs stay calm without extra Motion wrappers; respect `prefers-reduced-motion`.

## Sidebar tree
- The shared ListRow tree variant renders curriculum rows at every level. They are exactly `32 px` high at all breakpoints. Each row highlight uses the same `6 px` radius and spans the same left and right edges. Only row contents indent by depth. Labels remain `14 px` and weight 400 at all levels. The current row uses semibold. Use full Topic titles such as `Prealgebra` as top-level expandable folders, with Chapters, Units, and drills nested below. Use `foreground` on topic rows and `foreground-control` on deeper rows. Show the current leaf with a stronger neutral selected background plus `aria-current` that persists after pointer leave. Its expanded ancestor path stays visible.
- On desktop pointers, hovering a row for 500 ms opens a hover card to the right with the full title and curriculum ID. Touch uses the row menu to access Copy ID.
- The sidebar tree has no vertical guide borders, count backgrounds, or global Expand all / Collapse all / View toolbar. Keep per-folder chevrons and the sidebar shell collapse control. Programming shows `Labs` then `Drills` in one scrolling list under collapsible muted SectionHeader controls (`Labs` and `Drills`, each a keyboard-accessible button with `aria-expanded` and a small muted trailing chevron rotating from right when collapsed to down when expanded, respecting `prefers-reduced-motion` and persisted per viewer in `localStorage` defaulting to expanded). `Labs` renders as a `Topic → Chapter → (Unit when unit-scoped) → Lab` tree using lab titles as leaf labels and the same 32 px row surfaces, status dots, note/due badges, hover cards, menus, and selection states. `Drills` keeps the Topic → Chapter → Unit → Drill tree. Empty sections show a quiet message such as `No labs yet`.
- Each row uses one continuous, full-width rounded 32 px surface with separate buttons for the row and its menu. The trailing ellipsis appears on desktop hover, focus, selection, or while its menu is open, and is always available on touch. Resting titles use ellipsis. When actions are visible on desktop, long titles fade beside the actions without shifting the row. Every menu offers Copy ID. Drill menus also offer Reset and Delete. Reset and Delete identify the chosen drill and require confirmation; resetting another drill leaves the selected drill unchanged. Delete retains progress and workspace files and refreshes the tree, selecting an available drill or showing the empty state when the last drill is removed. Workspace controls use accessible `Math` and `Programming` names and navigate to the matching available workspace route.
- The Math and Programming links use the shared segmented navigation control. The two segments have centered icons and measure `32 × 32 px` on desktop and `44 × 44 px` in the mobile drawer. The drawer track adds `2 px` of padding.
- Interactive sidebar review fixtures live outside production routes and use synthetic data and callbacks.

## Search palette
- The sidebar Search row uses the shared ListRow with a 32 px visual height, neutral hover fill, focus ring, and edges aligned to the curriculum tree. Its hit area extends into the surrounding padding on touch. Reserve space for the muted shortcut (`⌘K` on Mac, `Ctrl K` elsewhere) at the trailing edge with at least 8 px between it and the label. Reveal it on pointer hover or keyboard focus. The icon-only control has a Search tooltip.
- Open Search by clicking it or pressing Cmd/Ctrl+K. The shared Dialog uses the Search scrim without blur, and cmdk handles the result selection. Its top edge stays fixed as results change, with a 12% viewport-height offset on desktop and a safe-area inset of at least 16 px on phones. The input receives focus on open. The close button and Escape dismiss it and return focus to the previous control. SegmentedChips renders the four filters All, Drills, Labs, and Units. Left/Right cycles them when the input is empty. With text, Left cycles only at the start and Right only at the end, with no text selected. Up/Down moves the highlighted result, and Enter opens it.
- The default view groups due units and drills from the existing review feeds under **Needs attention**, followed by **Recents** and **Actions**. Recents reuse the per-workspace, browser-local history of opened drills and labs. Actions open Daily review, the current drill's Review & Sync screen, or the other workspace when available.
- Queries fuzzy-match titles and IDs, including unit and chapter codes. Each result shows a single, ellipsized title and the same Math (Sigma) or Programming (Code) icon used in the workspace switch. Actions keep their own icons. Row icons and text are muted by default and use the foreground colour on hover or selection. Rows are 36 px on desktop and at least 44 px on touch. All can show both workspaces. Specific type filters browse the active workspace. A Unit opens its latest available drill or its scoped lab if it has no drill.
- Drill results reveal a 28 px ellipsis button on hover, selection, or keyboard focus, with a larger hit area on touch and an Actions tooltip. Tab can reach the selected drill's button. It opens the shared RowMenu with the same Copy ID, Reset, and Delete actions used in the sidebar. Reset and Delete close Search and open the corresponding confirmation for the chosen drill. Escape dismisses an open menu before it dismisses Search.
- The 671 px maximum width leaves 16 px gutters on phones. The search icon, first chip label, group headings, row icons, and footer share a 20 px horizontal inset. The list scrolls independently of the input, type chips, and keyboard help. The keyboard help footer appears at widths of 640 px and up. The close button has a 28 × 28 px visual box with a centered foreground-colour icon. The scrim uses black at 40% opacity in light mode and 50% in dark mode. The type chips use the foreground colour and are 28 px tall with 2 px gaps. The close button and chips extend their hit areas on touch. They show hover fill on devices that support hover and show a focus ring for keyboard focus. On touch, only the selected chip has a fill. Use the existing neutral surfaces and hairlines in both themes.

## Workspaces
- **Math**: similar-question strip at the top of the card when a variant bank matches. It starts with **Question N** and a ghost **+** control. The control unlocks on the first substantive check or Skip in the current cycle and keeps the same muted colour in every state (learner 2026-11-26: no inviting colour). Each press opens and selects one matching bank variant for the current cycle (preferring variants never served in earlier cycles in bank order, then wrapping from the first variant so the learner can re-practise after Reset). Opened tabs are scoped to the current cycle in saved order, and the control becomes unavailable when every variant has been served in the current cycle. The prompt, figure, answer input with `=` inside the field, and feedback follow the strip. Hint and equation set-up are available before answering and count as help. A substantive check or Skip unlocks steps (zero-leak parity on both main and similar tabs). After Skip in Daily Review, **Show steps** opens the solution. Similar questions offer full learner-action parity with the main question (Skip, Hint, equation set-up, Show steps, Mark diverged step, Self-score, Mistake tags, mistake/revisit notes, timer, and `P` pause shortcut) while staying isolated from the main score and review schedule.
- **Programming** (dashboard, no editor): brief → visible tests → status line `Tests  Lint  Types  Review` (✓ / ✗ / –) → primary action (Open in VS Code, or Copy `ตรวจโค้ด <ID> <QID>` once tests pass) → review history and explain question in collapsible sections → reference locked until review = pass.
- Studio opens and saves only source files listed for the drill in its server-side manifest. **Run Tests** reads the saved file from the current problem's manifest. An inline exercise can still submit its answer as code. Absolute, parent-relative, percent-encoded, and symlinked workspace selections are rejected. A missing valid source can still be materialized on open.
- **Labs**: same as Programming; the horizontal stepper shows each milestone's name, with a filled emerald check once every layer passes.

## Practice evidence

Studio autosave accepts problem drafts, mistake and revisit notes, the marked step, and the manual status preference for the canonical drill or lab. Explicit learner actions record help, skip, retry, mistake tags, and capped self-scores on the server. The answer checker and test runners persist their own results. The PRG rubric verdict still comes from the review-record workflow.

Studio resolves drill JSON, variant banks, lab configs, READMEs, visible tests, and progress files within their configured storage roots. A linked or non-regular record is unavailable to the reader. Progress saves reject unsafe destinations.

Practice Reset starts a new cycle through `POST /api/reveal` and keeps attempt history (including prior-cycle variant attempts) and the existing item schedule. `GET /api/variant?mode=list` reports current-cycle opened tabs and per-cycle availability after unlock. `POST /api/variant` with `action: "open-next"` opens the next variant for the current cycle (preferring never-served variants in bank order, then wrapping) and appends its tab. Token-scoped requests reopen or update individual sessions (including `skip`, `self-score`, `toggle-mistake`, `diverged-step`, `note`, `reveal-steps`, `reset`, and `duration`). Daily Review uses `start-review` to resume an unfinished server cycle and `reset-review` to start a retry while carrying forward any hint or equation set-up opened in the unfinished cycle. The item stays due until its first substantive check or explicit Skip is submitted for completion. The server keeps the first scheduled outcome for that day. The due list and completion response share the same public fields.

Reset also clears checker-added mistake tags from the previous cycle and keeps learner-selected tags. Progress records the check timestamp for each checker-added tag in `state.autoMistakes`. Older `concept-gap` tags require a current-cycle Skip after Reset. Other legacy tags with no recorded source are preserved. Review & Sync uses the resulting current tags.

## Scoring rule
One canonical rule drives every score, status, stepper circle, result card, Review & Sync row, and Notion mastery update (`practice-studio/src/lib/scoring.ts` in TypeScript and `progress_store.score_problem` in Python, locked in parity by `tests/fixtures/scoring_cases.json`). All scoring reads the **current cycle** (`cycleStartedAt`) only:

1. **Math / choice**: first substantive check correct with no help → `1` (`correct`, filled emerald). Correct after any wrong/partial check or after help (hint, equation set-up, steps/solution revealed before answering, worked example) → `0.5` (`assisted`, green outline). Partial / `equivalent_not_in_form` only → `0.5` (`assisted`) when partial credit `> 0`, else `0` (`wrong`). Wrong only → `0` (`wrong`, rose). Skipped → `0` (`skipped`, dashed zinc). No substantive attempt (including help opened without answering or input/parse errors) → `null` (`notTried`); input/parse errors render a neutral card, never green. *(Learner decision 2026-11-24: after Skip, the learner may open the solution; assisted scoring is unchanged.)*
2. **Lock after correct**: once a check is correct in the current cycle, the answer input is read-only, Check is disabled, and later checks are ignored. Press **Reset** to start a new cycle (keeping history).
3. **Self-score**: may only **lower** the computed score (e.g., guessed `1 → 0.5` or `0`), or set a score when no automatic score exists. It never raises a wrong or skipped item and never clears `skipped`; outcome follows the final score.
4. **Mark diverged step**: a learning note only — it never changes a `null` score into `0.5` and never lowers a first-try `1`.
5. **PRG drills and labs**: all tests passing **and** latest review in the cycle is `pass` → `1` only on a clean first passing run with no hints and no earlier failing run or `revise` review in the cycle; otherwise `0.5`. Passing tests with no review yet → `score: null`, shown as **Awaiting review** consistently across stepper, tiles, rows, and summary. Failing tests or latest review `revise` → `0` (`wrong`).
6. **Similar questions**: scored with the exact same rule as the main question (wrong → correct is `0.5` `assisted`, locked after correct), while remaining isolated from the main score and review schedule.

- Secondary text uses the `foreground-secondary` token (`--foreground-secondary`; light zinc-500, dark #8a8a93, both AA); do not hard-code zinc greys for secondary text in new code.
