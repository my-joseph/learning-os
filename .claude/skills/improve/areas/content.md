# Learning content assessment playbook

Assess one subject/unit scope at a time. Read `rules/00_core.md`, `rules/02_pedagogy.md`, and the applicable subject rules. Content written to drills, vaults, and docs stays English; do not reveal drill prompts, answers, steps, or hidden tests before a real attempt.

## Inspect

- Run the `drill-quality` skill for the chosen units. Review `vault_report`, `weak_spots`, and Similar variant coverage; distinguish content/vault quality from learner-specific progress and use pilot data if a workflow needs state.
- Check archetype coverage, variant coverage, levels, traps, and evidence gates against current drills and vaults. Do not hand-edit `id_map.json` or touch `progress/`.
- Compare proposed topic gaps with `docs/backlog.md`. Treat roadmap items as eligible only when their unit/topic is actually starting, and check learner deferrals before proposing content work.
- Roadmap delivery uses existing authoring routes: `new-math-drill`, `new-code-drill`, or `synthesize-source` as appropriate. Confirm their current instructions and command help before recommending a route.

## Better means

- Better evidenced coverage of the intended skills, levels, and common traps.
- More useful variants with no answer leakage and quality gates still passing.
- Content gaps are addressed when their learning scope is active, with measurable vault/variant/quality outcomes.
- Preserve strong existing explanations, examples, and learner-authored content; avoid generic rewrites.

## Report

Name the units, evidence sources, coverage measures and thresholds, strengths to preserve, and bounded content/vault changes with expected outcomes. Keep all authored learning content English.
